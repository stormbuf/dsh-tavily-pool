# dsh-tavily-pool 使用说明

[English](./usage.md) | **简体中文**

用 [Tavily](https://tavily.com) 替代 DeepSeek Harness 内置的 web 搜索与网页抓取，支持多把 API 密钥、余额感知调度、失败自动切换与用量统计。

## 安装

```sh
dsh plugin add dsh-tavily-pool
```

安装后重启 DSH，打开 **设置 → 插件**，即可看到本插件的配置卡片。

## 添加密钥

本插件**不读取环境变量**，也不读取 DSH 的 credentials 服务——密钥只能在面板里手动粘贴。

1. 打开 **设置 → 插件 → dsh-tavily-pool**
2. 在密钥输入框粘贴一把 Tavily API key（形如 `tvly-...`）
3. 点保存

一次要加多把时，点**「批量添加」**：弹出一个文本框，一行粘一把，确认即可全部加进池里。两侧空白会被忽略，空行不算密钥，池里已有或本次粘贴里重复的行会被跳过——加完之后卡片会如实告诉你加进去了几把、跳过了几把。

同一把明文提交两次不会占两个槽位：单把添加也做查重，重复时卡片会说一句「这一把已经在池中了，没有新增」。

要一次删掉多把时，点**「批量删除」**：弹框里勾选，确认后**一次落盘**删掉所选。单把删除仍是逐把的，而批量走这条出口——一次误粘把池子撑大之后，逐把点太慢。

写入是有上限的：单把密钥最多 512 个字符（真实密钥约 50），一次粘贴最多 200 条，池内最多 200 把。超限时服务端**整批拒绝**并说清上限、实收条数与是哪一行，而不是截断——静默截断会让用户以为写进去了。

池内最多 200 把。列表只显示脱敏形式（`tvly-...xxxx`），明文仅保存在本机：

```
~/.dsh/dsh-tavily-pool/keys.json
```

该文件权限为仅当前用户可读。本插件不提供任何返回密钥明文的接口，也不提供导入/导出功能。

### 运行期间手工编辑这个文件

**文件是密钥集合的真源，DSH 进程内的池只是它的一份缓存。** 运行期间对这个文件的改动算数：

| 外部改动 | 结果 |
|---|---|
| 补一把密钥（手写一条记录，或由另一个实例/进程添加） | 会被读进来，不会被内存里那份旧池覆盖 |
| 删掉一把 | 不再被用于搜索或抓取，也不会被下一次写入写回 |
| 改 `label` / `disabled` 等记录字段 | 本进程没有正在改它时以文件为准；本进程刚改过的那条以本进程为准 |
| 加一个本版本不认识的顶层键（例如更新版本写下的字段） | 原样保留，不会在下一次编辑时被抹掉 |
| 改 `order`（先后顺序） | 顺序以进程内的池为准，手工改它重启后才生效；记录集合本身仍以文件为准 |

反方向的规则同样明确：**每把密钥的调用统计与余额缓存以进程内的运行期记录为准**，落盘时覆盖文件里的同名项——它们不从文件读回来。

生效时机没有「立刻」的保证：一次外部改动最迟在**下一次落盘**（一次搜索或抓取之后的记账、一次余额刷新、一次面板编辑）或**下一次打开面板**时被吸收。

两条边界要清楚：

- **删除整个 `keys.json` 不等于清空密钥池。** 文件读不出来（不存在、或内容坏掉）时插件什么都不做，手上的密钥不会被丢掉。要清空请在面板上逐把删除。
- **别把文件写坏。** 内容不是合法 JSON 时插件以空池继续并如实报错（错误文案里带着是哪个文件），而**坏文件期间面板上的任何写入都会把它换成一份只含新密钥的池**——这是「以空池继续」这条既定取舍的代价。

## 开关

有两个**独立**开关：

| 开关 | 关闭时的行为 |
|---|---|
| **搜索接管** | 搜索请求转交 DSH 官方搜索提供方 |
| **抓取接管** | 抓取请求转交 DSH 内置的本地 HTTP 抓取器 |

两者互不影响——例如你可以只用 Tavily 搜索、同时保留内置抓取。

开关改动**即时生效**，无需重启。

## 搜索参数

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| **搜索深度** `searchDepth` | `basic` / `advanced` / `fast` / `ultra-fast` | `basic` | 相关性与延迟的取舍。`advanced` 每次计 **2 积分**，其余三档计 1 积分 |
| **结果数上限** `maxResults` | 1–20 | 10 | 单次搜索最多取回多少条来源 |
| **主题** `topic` | `general` / `news` / `finance` | `general` | `news` 适合时事，`finance` 适合金融 |
| **生成答案** `includeAnswer` | 开 / 关 | 关 | 让 Tavily 额外生成一段答案，作为搜索结果的正文返回 |

参数改动同样**即时生效**，下一次搜索就带上新值。

`maxResults` 是**上限**而非保证：模型调用搜索时可以要求更少，此时以它要的为准；结果最终还会由 DSH 的接缝再截断一次。下界是 1——官方接口文档写的是 0，但实测 `0` 会被上游以 `400 Invalid max results.` 拒绝，而这类错误不会重试也不会切换密钥，因此面板不接受它。

宿主自己的编排还压着一层上限：DSH 的 `tool-web` 每次搜索都带着 `searchMaxResults`（默认 **8**）向本插件要结果，插件取它与面板值的**较小者**发往 Tavily。因此在 DSH 上，把 `maxResults` 填成 9–20 与填 8 的效果完全相同，只有往小调（1–8）才会真的改变取回的条数。

深度与条数是两个独立的维度：**深度决定「搜得有多彻底」，条数决定「给回几条」**。计费只看深度（`advanced` 2 积分，其余三档 1 积分），条数不影响积分。

## 抓取参数

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| **抽取深度** `fetchDepth` | `basic` / `advanced` | `basic` | `advanced` 取回的内容更多，积分消耗也**翻倍** |
| **返回格式** `fetchFormat` | `markdown` / `text` | `markdown` | Tavily 返回的文本形态；`text` 会增加上游延迟 |

抓取**没有按次可传的参数**：DSH 的抓取请求类型**只有 `url` 一个字段**，模型无法对某一次调用单独指定深度或格式。这两项设置是唯一的改动途径。

抓回的页面以**纯文本**返回，不会被当成 HTML。Tavily 给的本来就是 markdown，插件据实告诉 DSH 这是文本、由它原样透出；标成 HTML 会让 DSH 对一份 markdown 再做一次转换，把内容弄坏。

## 调度

密钥池默认按**余额优先**调度：

- 每把密钥的余额 = **上限 − 已用**。上限优先取这把密钥自己的 `key.limit`；它为 `null` 时退回**该密钥所属账号**的套餐上限 `account.plan_limit`——免费账号的 `key.limit` 恰好就是 `null`，只看它会把 1000 积分/月的账号读成「无限额度」
- 剩余额度多的先用
- 只有密钥级与账号级都没有上限时才算「无限」，它排最前
- 余额**未知**的密钥垫底（未知不等于零）
- 同一额度档内轮转打散
- **每把密钥各算各的**：插件不判断哪几把密钥属于同一个账号（官方不提供归属信息），因此某个账号下有多把密钥时，各把会各自看到同一份账号额度

### 调度策略

`schedulingPolicy` 决定候选密钥的**排序**方式，两种取值：

| 取值 | 行为 |
|---|---|
| `balance`（默认） | 按剩余余额决定先后；同额度档内轮转 |
| `manual` | 严格按密钥池里显示的顺序依次尝试，**不参考余额** |

「手动顺序」意味着列表顺序就是调度顺序——上下移按钮因此不再是纯展示。`manual` 下每次都从列表里第一把可用密钥开始（**不轮转**），它失败后请求才轮到下一把。

**它只影响排序。** 停用、冷却、额度耗尽、永久失效的密钥在**两种**策略下都是硬排除——手动顺序不是「无视状态硬打第一把」，否则一把坏密钥就能拖垮整个池子。

策略改动与其它设置一样**即时生效**。

某把密钥临时失败（限流 `429`、服务端 `5xx`）时会被**冷却**，冷却期内**不参与**密钥选择（即使池内其余密钥都不可用，也不会使用它）；冷却结束后自动恢复。

若**所有**密钥都在冷却中，插件会**等待**最早到期的那把，而不是立刻失败——但仅当那一刻落在等待预算之内。超预算时它不会傻等：等一个到不了的到期时刻只会把失败推迟，因此它会立刻返回上游的错误，并保留原始响应里的 `request_id`。

池中密钥的失败会触发**故障切换**：插件自动改用另一把。同一把密钥在一次请求里不会被重复尝试。

**额度耗尽**（`432` / `433`）与冷却不同：它不是「等一会儿」的问题，而是这把密钥在当前计费周期内没量了。这种密钥会一直**不被选中**，直到确认它恢复为止。

Tavily 的用量在**每月 1 日**归零。由于官方没有说明该重置发生在哪个时区，插件会在跨越月起始后**自动探测**：从 UTC 月起始开始，每隔 6 小时检查一次，最多持续 48 小时——这个窗口足以覆盖全球任何一个时区的月初。探测只调用余额查询接口，**不消耗积分**。

你也可以随时在面板上点「刷新余额」立刻检查。若 48 小时内始终未恢复，通常意味着需要到 [Tavily dashboard](https://app.tavily.com/account/plan) 提高限额，而不是等时间。

若池内已无可用密钥，请求会按上面的开关设置**回落**。回落有三种触发情形：搜索开关关闭、密钥池文件损坏（此时以空池继续，并在日志里报告该文件）、以及池内没有任何**可能在本次请求内**恢复的候选（空池、全部停用、全部额度耗尽或永久失效）。

> 注意「没有任何可用密钥」与「刚试过、刚失败」是两回事：后者手上有上游的真实答复，插件会把它如实上报（含 `request_id`），**不会**换一个来源重试。

回落目标自己也可能不可用，两种情形会给出**不同的错误码**，因为要用户做的事不同：

| 错误码 | 含义 | 该怎么办 |
|---|---|---|
| `TAVILY_FALLBACK_CREDENTIAL_MISSING` | 官方凭据**从未配置** | 配一把（面板的 Models 页、环境变量 `DEEPSEEK_API_KEY`，或 `web-search-deepseek` 的 `apiKey`） |
| `TAVILY_FALLBACK_CREDENTIAL_INVALID` | 官方凭据配了，但上游以 `401` / `403` 拒绝 | 换一把，而不是再配一次 |

两条错误都会带上「为什么离开 Tavily」，因为只看到一条关于 DeepSeek 凭据的错误，会让人去修错的东西。

密钥失败分为三类：

- **永久失效**（如响应体明确指示密钥被吊销或无效）——需要你处理
- **临时失败**（限流、服务端错误）——冷却后自动恢复
- **额度耗尽**（`432` / `433`）——只在确认余额回升后才恢复；可到 [Tavily dashboard](https://app.tavily.com/account/plan) 提高限额

> 本插件**无法得知**两把密钥是否属于同一个账号（官方 API 不提供归属信息），因此不区分「账号级」与「密钥级」故障，一律按**单把密钥**处理。

## 余额刷新

面板上的「刷新余额」按钮会调用 Tavily 的 `/usage` 接口拉取官方余额。

Tavily 对该接口限流为 **10 次 / 10 分钟**，因此本插件对每把密钥做了配额预占，不会触发限流。刷新失败时**保留旧值并标记为陈旧**，不会用 0 覆盖。

本插件**不推测计费周期**——余额一律以官方 `/usage` 返回的当前周期数值为准。

## 计费口径

- **搜索**：`basic` / `fast` / `ultra-fast` 为 1 积分，`advanced` 为 2 积分
- **抓取**：每 **5 个成功抓取**的 URL 计 1 积分（`basic`）或 2 积分（`advanced`）；失败的 URL **不计费**

因此单次抓取通常消耗 **0 积分**：「每 5 个成功 URL」的 5 是**跨调用累计**的，而一次 DSH 抓取只带一个 URL，所以只有每第五次成功抓取才会跨过一档。

插件按密钥累计成功 URL 数、自己把累计值换算成积分，不读上游在响应里回传的 `usage.credits`：那是上游按它自己的累计口径取整的结果，一次确实花了积分的响应也常常写着 `0`。本地记账同时让余额估计保持诚实——按请求各记 1 分会让它比 Tavily 的账单快五倍地掉，而那个估计正是决定先用哪把密钥的依据。

## 调用历史

每次 Tavily 调用都会留下一条记录——用的哪把密钥、哪个端点、成没成、消耗多少积分、耗时多久，
以及上游给了 `request_id` 时的那个 id——写在：

```
~/.dsh/dsh-tavily-pool/history.json
```

面板上画出一张**最近 14 天的每日积分消耗**曲线（搜索与抓取各一条线，因为两者量级差得太远，
共用一套纵轴刻度会让抓取那条贴着零线看不出来），外加一张最近调用的明细表。

**一次请求可能留下多条记录。** 故障切换意味着每次尝试都是一次真实的上游调用，因此「试了两把
密钥的搜索」会留下一条失败、一条成功。这是有意的：那些尝试各花了各的积分，只记请求级的一条
会把它们藏起来。

### 裁剪

两条限制**同时**生效，取更严的那个：

| 限制 | 取值 | 理由 |
|---|---|---|
| 条数 | 500 条（保留最新的） | 防止高频使用把文件写爆 |
| 时间 | 30 天 | 防止低频使用时一份半年前的记录永远占着位置 |

因此文件不会超过约 100 KB。裁剪发生在**每次写入时**——没有后台任务，也没有「进程刚好退出在
两次裁剪之间」的窗口。

时间窗口以**最新一条记录**为基准，而不是当前时刻：从别处复制来的历史、或系统时钟被改过之后
留下的那份，不该在被读到的瞬间被清空。

积分未知的记录**不写** `credits` 字段，而不是写 `0`——于是「这次没花钱」与「不知道这次花了
多少」在历史里同样分得清。这类记录会出现在明细表里，但不进曲线。

历史写不进去时调用不受影响——插件在日志里报一句，曲线少掉那几条而已。读不出来时面板会如实
说明，而不是显示成「没有调用」。

## 手动回退

若插件加载失败导致搜索不可用，DSH 会报 `WEB_PROVIDER_CONFIGURED_MISSING`。此时把 profile patch 里的提供方改回官方值即可恢复。

编辑：

```
~/.dsh/profiles/<profile>/cordis.patch.yml
```

找到覆盖 `web` 行的那一段，把 `searchProvider` 与 `fetchProvider` 改回官方值：

```yaml
- id: web
  config:
    searchProvider: deepseek-official
    fetchProvider: http
```

> ⚠️ **两个字段必须同时写全。** patch 的 `config` 是**整体替换**而非合并；只写一个会让另一个字段变为「未配置」，从而走自动选择——这不会报错，但行为不再是你要的。

若只想回退其中一项，改那一项、另一项继续指向 `tavily`，但**两行都要在**。各自对应哪个官方值见上面[开关](#开关)一节的表。

保存即可生效，无需重启（profile 的 `patchReload` 为 `live`）。

`dsh plugin add` 初始化的 profile 就是这个形状：`dsh-tavily-pool` 出现在该 profile 的
`dsh.profile.bundles` 里，排在 `@deepseek-ai/dsh-base` 与 `@deepseek-ai/dsh-web-app` 之后，而提供方的
pin 是以 bundle patch 层的形式生效的。你自己的 `cordis.patch.yml` 在**所有 bundle 层之后**应用，
因此它能覆盖那两个字段。

改完后可以停用或移除本插件。

## 与其它 DSH Tavily 插件的区别

DSH 生态里还有两个同主题插件，本插件与它们的定位不同：

| | `szmy-haruhi/dsh-tavily` | `@yuuz12/dsh-tavily` | **dsh-tavily-pool** |
|---|---|---|---|
| 密钥模型 | 单密钥 / 免密钥模式 | 多密钥池 | **多密钥池** |
| 余额感知调度 | 无 | 有 | **有** |
| 故障切换与冷却 | 无 | 有 | **有** |
| 用量统计 | 无 | 有 | **有** |
| 网页抓取接管 | 无 | 无 | **有** |
| 接管方式 | 静态配置固定 | 运行时改写内部字段 | **静态配置固定** |

本插件**不支持**免密钥（keyless）模式——免密钥调用无法归属到你的账号，因而无法记账，也无法显示余额。
